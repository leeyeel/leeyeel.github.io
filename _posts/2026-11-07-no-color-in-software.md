最近一段时间做了一段密集的全栈开发工作，需要搭建很多基础设施，在这个过程中发现了一些有意思的事情。

老牌的云服务商亚马逊AWS, 谷歌GCP，微软Azure，他们早在十年前甚至更早就推出了命令行工具，比如AWS CLI, gcloud, az等。使用这些工具不需要再在web页面上进行复杂的点点点配置，对于熟悉命令行的运维人员来说，直接使用命令行可以大大提高效率，也更容易做成脚本。

这两年随着大模型的兴起，这种纯命令行的方式不仅没有消亡，反而重新焕发了生机。比如我们熟悉的域名服务商GoDaddy推出了godaddy, 甚至连Sentry都推出了Sentry CLI。我自己也实际体验使用codex来操作这些CLI工具，非常丝滑。比如让codex 添加删除godaddy的域名解析，绑定域名证书，整个过程没有切屏，没有多标签反复横跳，没有繁琐的2FA逐次验证，也没有因为文档更新不及时因此无法按照教程找到正确的按钮位置的问题。所有的基础设施操作，在几行终端输出与标准退出的闭环中，几秒内全部交付完毕。这个过程让我感觉到，过去二十年为 Web 图形界面所做的一切深度优化、流畅动效和酷炫设计，在 AI Agent 面前，不仅正在变得无关紧要，甚至正在变成障碍。

![AI Agent 与命令行]({{ '/assets/20261107/1.jpeg' | relative_url }})

### 一、 设计目标是“最蠢的客户也会用”，但是现在的客户是Agent

如果回顾过去的前端与产品设计史，我们几乎把所有的智力都倾注在了“如何服务愚蠢的人类”上：

为了减少用户的认知负荷，我们需要设计精妙的折叠卡片、浮动弹窗和抽屉导航；为了让操作更有掌控感，我们调教了丝滑的贝塞尔曲线微交互、骨架屏和异步加载水波纹；为了争夺注意力，我们用高饱和度的色彩定义主操作按钮，用醒目的警示红提醒错误表单。甚至为了让风格统一，我们发明了拟物化，扁平化，新拟态等一大堆风格。

但在以大模型为核心的执行范式下，这些东西全成了“数字噪音”。页面确实越来越漂亮了，交互越来越丝滑了，但骨架也越来越臃肿。每一座云厂商的后台控制台，都变成一坨永远解不开乱糟糟的线头（实名吐槽腾讯云，文档更新不及时，前后矛盾垃圾玩意）。点选一个配置、更新一条 DNS、开辟一个鉴权路由，需要人类在几十个标签页和繁复的表单弹窗里反复横跳。如果你让Agent 通过浏览器去操作复杂的 Web 页面，它需要截取视口图像、解析 DOM 树、计算渲染盒模型的坐标、处理动态渲染的异步加载延迟，还要花费极大的精力去伪装以抵御反爬检测。

![codex操作clerk]({{ '/assets/20261107/2.jpeg' | relative_url }})

而使用命令行CLI 直接就是降维打击：每条指令对应一个精确的 API 行为，遵循标准输入输出，有异常还会返回退出码，如果遇到报错，Agent 捕获错误后还会自动修改参数重新尝试。整个过程完全绕过了人类发现错误，解决错误，重新尝试的这个臃肿的流程。

过去原本被我们视作核心竞争力耗费巨大精力设计的，产品经理口中的“连傻13用户也会用”的UI，在标准命令行的极速吞吐面前立马显得像个智障。

### 二、 大模型不仅重塑程序员，也会重塑产品

程序员的节奏早就被颠覆了，这甚至不需要解释。但更深远的影响，发生在软件产品本身。大模型不仅在重塑开发流程，更在彻底重塑软件的最终形态。

![复杂UI设计]({{ '/assets/20261107/3.jpeg' | relative_url }})

传统软件之所以需要复杂的 Web 展示层，是因为人类需要视觉来理解数据层级。我们需要表格、柱状图、Tab 切换页、进度条，本质上是因为人类大脑无法直观消化长串的原始数据流，计算机被迫需要停下来等待人类理解。但是，当人类与软件之间隔了一层无处不在的智能体时：软件的第一消费者不再是人类，而是 Agent。软件不再需要靠炫技的前端动效来证明它的技术实力，也不再需要处心积虑地设计用户动线去“引导”点击，因为 Agent 从不需要心理暗示。

未来的软件，会越来越倾向于直白、规则、极其结构化的内容呈现。复杂的设置面板正在失去它的受众，无论是繁琐简陋，还是极尽奢华，都将不再是人们关注的重点。

### 三、 软件正在失去颜色，是因为他不再需要颜色

在过去的 UI 设计中，颜色承担着繁重的职责，而且，至少我们这一代程序员早就被训练成条件反射，红色代表危险因素必须停下（当然，大A除外！），绿色代表 Success（同样大A除外！），予以正向反馈，蓝色是超链接，指示前进方向，灰色是禁用态，需要划定操作边界。但在人机协同的下一个时代，命令就是命令，状态就是状态，布尔值只有 0 和 1。当 Agent 直接在底层完成调度并把最终摘要交付给你时，那些用来提示“哪里需要点击”、“哪里发生冲突”的高亮色块，瞬间失去了存在的根基。

未来的软件界面，或许会不可逆地走向黑白与极简。甚至人类可能连这层黑白文本也懒得看，也看不懂，就像开会就是互丢AI文稿一样，直接沦为“最终确认授权”的签字工具。我们从当初学习C语言的那个黑框开始，一步一步好不容易学会了设计复杂的界面酷炫的效果友好的交互，最终才发现：真正硬核的生产力还是那个闪烁着光标的黑框框。

所以下次需求评审，产品经理再鸡鸡歪歪要求“改这改那让按钮更醒目”时，你大可以把这篇文章甩给他然后真诚的问他一句：

> “你的用户连屏幕都不用，你这颜色是做给谁看？”
